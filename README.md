# Document Intelligence & Multi-Source Search Platform

A retrieval-augmented Q&A system for document collections — upload PDFs, scanned images, Word docs, and spreadsheets, then ask natural-language questions and get answers grounded in cited evidence, with conflicting sources surfaced rather than silently merged.

Built end-to-end: document ingestion → OCR/structure extraction → hybrid dense+sparse retrieval with reranking → grounded generation with citation validation → conflict and confidence detection → multi-turn conversation memory.

---

## Highlights

- **125/125 backend tests passing, 90.2% coverage** (enforced at 70% minimum via CI gate) — verified independently, not just claimed
- **Hybrid retrieval**: dense embeddings (BGE-M3) + sparse (BM25-style) search, fused and reranked, rather than plain cosine-similarity lookup
- **Anti-hallucination by design**: every citation is checked against retrieved chunk metadata before it's shown; the system explicitly answers "insufficient evidence" when confidence is low instead of guessing
- **Conflict detection**: when two sources disagree (e.g. two reports quoting different revenue figures), both are surfaced side-by-side rather than one silently winning
- **Numeric answers are computed, not hallucinated**: percentage changes and sums are calculated programmatically from retrieved data, never generated by the LLM
- **CI on every push**: GitHub Actions runs the backend test+coverage gate and a frontend build + Vitest suite

## Architecture

```
Document Upload
      ↓
Document Type Detection
      ↓
Multi-Pipeline Processing      (PyMuPDF | PaddleOCR-VL-1.6 | python-docx | table parser)
      ↓
OCR / Structure Extraction     (layout-aware: paragraphs, headings, tables, formulas, images)
      ↓
Chunking + Metadata            (page-scoped, tables kept whole)
      ↓
Embeddings                     (BGE-M3, with a deterministic local fallback)
      ↓
Hybrid Retrieval                (dense + sparse + fusion)
      ↓
Reranking                       (BGE-reranker-v2-m3)
      ↓
Grounded Generation             (citation-validated, conflict-aware)
      ↓
Answer + Source Attribution
```

PDF routing picks the text-layer or OCR pipeline per document based on extracted text density; scanned PDFs and images both route through PaddleOCR-VL.

## Getting Started

### Backend

```bash
cd backend
python -m venv .venv
source .venv/bin/activate        # Windows: .venv\Scripts\activate
pip install -r requirements.txt
cp ../.env.example .env
uvicorn app.main:app --reload
```

API docs at `http://localhost:8000/docs`, health check at `/api/health`.

### Frontend

```bash
cd frontend
npm install
npm run dev
```

Visit `http://localhost:5173` (proxies `/api` to the backend — run the backend first).

### Tests

```bash
cd backend
pytest tests/ -q --cov=app --cov-report=term-missing --cov-fail-under=70
```

125 tests, ~90% coverage. OCR and external model/provider calls are exercised against deterministic fakes in the test suite, so tests run fast and don't require GPU, network, or API credentials.

### Docker

```bash
docker compose up --build
```

### Optional: real embedding/reranker weights

The base install uses a local hashing fallback for embeddings so the app runs without a GPU or large downloads. For real BGE-M3 embeddings and reranking:

```bash
pip install -r ../requirements-ml.txt
```

## Reliability Strategy

- Every citation is validated against actually-retrieved chunk metadata before being shown to the user — no fabricated sources
- Explicit "insufficient evidence" response when retrieval confidence is low, rather than a confident-sounding guess
- Conflicting sources are surfaced side-by-side, never silently resolved by the LLM
- Calculations (growth %, sums, comparisons) are computed in code from retrieved numbers, not generated as free text

## Example queries the system is designed to handle

- "Compare revenue between 2024 and 2025."
- "What is the total amount on invoice INV-2026-0187?"
- "Why do the two reports show different revenue figures?" *(conflict identification)*
- "What about 2023?" *(multi-turn follow-up, resolved from conversation context)*
- "What was the company's revenue in 2035?" *(expected: insufficient evidence, not a hallucinated number)*

## Current Limitations

- Real PaddleOCR-VL and BGE-M3/reranker model weights haven't been exercised against live inference in every environment this was built in — the routing, parsing, and integration code is fully tested against deterministic fakes, but a GPU/network-enabled run against the actual weights is still worth doing before treating OCR/embedding quality numbers as final.
- No live LLM provider call has been made without an API key configured — the client code and its failure paths are tested, but end-to-end generation quality depends on whichever provider you connect.
- `docker compose up` is configuration-validated (`docker compose config`) but hasn't been run end-to-end in every build environment.
- Page-level mixed text/image routing isn't implemented — each document is routed as a whole to either the text-PDF or OCR pipeline.
